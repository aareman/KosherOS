KosherOS Admin

The admin app, redrawn so a parent can see what is going on

Today the app is a list of settings that happens to hold people. The redesign turns it around: the first thing on screen is what needs an answer and what the filter is actually doing, and each person's protection reads in one line of plain words before anyone opens a dialog.

Three ways to arrange the home screen are drawn below, then the account screens that all three share. Everything stays libadwaita: the windows are drawn with its real tokens so what you see is what GTK will build. Light Adwaita is shown; the page follows your theme, as the app would.

Example family, example numbers. Where a screen needs data kosherd does not record yet, the note says so.

Five moves every direction makes

  • 1Requests and filter health come first. A waiting request is the only thing anyone is blocked on, and a filter that has quietly stopped is the only thing that is dangerous. Both sit at the top and stay out of the way when there is nothing to say.
  • 2Every person gets a one-line status in a parent's words: the preset, what is hidden, what happened today. No opening a screen to find out how someone is set up.
  • 3Machine-wide settings leave the people list. Apps, word lists, ad blocking, the guardian password and updates are about the computer, so they live under "This computer" instead of as buttons at the bottom of Profiles.
  • 4Drift from a preset is named and reversible. "Custom" becomes "Child, with 2 changes: Sports also blocked; YouTube stricter", with a Reset button, so nobody wonders what was fiddled with.
  • 5A block can become an allow in one click from the list of what was blocked, without waiting for the person to file a request.
Sepia pins mark notes; they are not part of the UI.needs kosherd marks data the daemon must start recording.
Direction A

The Settings layout: people in a sidebar, one overview pane

The most conservative move. A navigation split view like GNOME Settings, so every person and every computer-wide setting is one click away and always visible. The overview pane carries requests, health and today's summary.

  1. 1Health speaks when it is fine, too. The current "Needs your attention" group only appears on failure, so a healthy machine says nothing and a parent cannot tell "fine" from "not checked". One row for the problem, one row for what is running, with the time it was last checked.
  2. 2The person list is the navigation. Preset and drift are the subtitle, a request count is the badge. Selecting a name replaces the pane; no push, no back button, and the list stays in view so switching between two children is one click.
  3. 3Computer-wide settings have their own section with the current value as the subtitle, so "Is ad blocking on?" is answered without opening anything.
  4. ·Requests show why. The page title, the category that blocked it and the child's note, with the three answers inline. Today this is a URL and an Allow button that opens a second dialog. needs kosherd to store the page title and the blocking reason with each request.
  5. ·"Today" counts per person. needs kosherd to keep a rolling count of blocks per account; the proxy and resolver already make the decision, they only have to write it down.

Best when: the window is usually wide and the family is small. It is the smallest change to the current code: the ViewStack and the Profiles action list become a sidebar, and the detail page becomes the pane.

The family board: one card per person, at a glance

The home screen is the family. Each card is a person's protection in three lines and what happened today, so a parent reads the whole house in one look. Requests sit under the cards; computer-wide settings are a row of tiles at the bottom.

  1. 1Health is a thin banner, not a group. Amber with one sentence and a fix button when something is wrong; when all is well it shrinks to the green "Filter running · checked 2 min ago" tag beside the family heading. Either way, it never pushes the family below the fold.
  2. 2A card is the protection, not the settings. Four lines, always in the same order (web, pictures, video, apps) so the eye compares across children. "Child, with 2 changes" is the preset drift; the footer is what happened today. Clicking opens the detail page from Direction D.
  3. 3Tiles for the computer sit under the family, always the same five in the same order: Apps, Word lists, Ads and trackers, Guardian, Updates. Each shows its state, and each opens a plain page. If the family outgrows one screen they also belong in the header bar menu, so they are never more than one click away. The guest account is a card like everyone else, dashed while off, so it is discoverable without cluttering the list.
  4. ·Requests stay one click. Same three answers as Direction A. When there are none, the group is gone rather than saying "no requests".

Best when: the parent opens the app to check on the kids more often than to change settings, which is the case this product is built for. Costs more layout work: Gtk.FlowBox of cards with a fixed line order, and a stable card height.

  1. 1Drift has a name and a way back. Today an account that departs from a preset by one switch reads as "Custom", which tells a parent nothing. Here it reads "Child, with 2 changes", and "Reset to Child" undoes them in one guardian-gated call. The existing profiles.matching() only needs to return the diff instead of None.
  2. 2The protection strip is the account in six chips, always in the same order. Chips in blue are the changes from the preset; everything else is the preset speaking. Clicking a chip jumps to its tab.
  3. 3Blocked today turns into allows. "Allow" on a blocked row writes a page rule (or a whitelist entry for a whitelist account) with the guardian gate, exactly like approving a request. The parent no longer has to wait for the child to ask.
  4. 4A short history with Undo answers "who changed this?" in a household with two admins. needs kosherd to record changes per account with the acting admin.
  5. ·Six tabs, not three. Filtering, Pictures & words, YouTube and Apps each get a full page instead of a row that opens a dialog. Fewer nested dialogs, and each page has room to explain itself.

  2. 2Categories on the page, in two columns. Fifteen rows fit without scrolling. "Child preset" re-applies the preset's set; All and None are the bulk buttons you asked for.
